# 0008. Contract generation

- Status: Accepted
- Date: 2026-10-05

## Context

"Data contract" in `docs/architecture.md` requires a JSON Schema exported
from the Pydantic models and TypeScript types generated from it. It does
not say where they live, how they are generated or how they are checked.

## Decision

- The models live in `api/app/feeds/<feed>.py` on the `FeedModel` base. The
  wire format uses camelCase keys, rejects unknown fields and always
  carries optional fields, as `null` when unknown.
- One schema per feed at `api/schemas/<feed>.schema.json`, exported in
  serialization mode without per-field titles.
- Types are generated by `json-schema-to-typescript` (exact pinned version)
  into `web/src/lib/contract/<feed>.ts`, formatted with the Prettier
  config of `/web`.
- One command regenerates both: `scripts/contract.sh`.
- The check is two tests inside the existing gate steps: api pytest
  compares the schema with the models, and web Vitest compares the types
  with the schema. `scripts/gate.sh` is unchanged.
- Rejected alternatives: new steps in `gate.sh`, which would add gate
  commands for one concern; generating the types in the api job, which has
  no Node.

## Consequences

- A contract change touches both apps in one change.
- A hand edit or a stale file fails a gate.
- `/web` gains one dev dependency.
- The web job reads a file under `api/`.
